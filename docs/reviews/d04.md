# D04 review

Review of `feat/d04-map` against `docs/plans/d04-map.md` (`requesting-code-review`, `differential-review`,
`accessibility`, `react-best-practices`). Size: medium; strategy: focused on data contracts, CSP and keyboard
access.

| Area | Risk | Notes |
| --- | --- | --- |
| CSP generation at build | High (security headers) | `connect-src` now names the exact Supabase origin (https/wss); the build fails without a URL or with plain http outside localhost. Tested. |
| Supabase client | Medium | Publishable key only; configuration validated with zod; RPC responses validated before use. |
| Map interaction | Medium (accessibility) | The SVG is one labeled image; regions are not tab stops. The combobox search (WAI-ARIA 1.2 pattern with `aria-activedescendant`) and zoom buttons cover keyboard users; selections are announced politely. axe passes on the map page. |
| Performance | Medium | Map code and the 0.9 MB geometry load only on `/map`; the geometry is a hashed asset with an immutable cache (e2e checks the header). Initial JS stays at 89 kB of 170 kB. The zoom transform is applied through a ref, not React state. |

Findings: none critical or important. Accepted: the map is a single world copy (no endless horizontal pan
like the prototype); the in-game map screen adds resources and battles in their modules.
