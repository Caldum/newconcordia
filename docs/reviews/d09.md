# D09 review

Review of `feat/d09-ledger` against `docs/plans/d09-ledger.md` (`requesting-code-review`,
`differential-review`, `accessibility`). Size: large; strategy: focused on money integrity, idempotency and
the one public function that moves money.

| Area | Risk | Notes |
| --- | --- | --- |
| Ledger integrity | High (money) | One posting row debits and credits the same amount, so no unbalanced entry can be written. Balances change only in `game.post`, under locks taken in id order. Check constraint: no negative balance except issuers. pgTAP: 1,000 random transfers keep totals and never go negative; every currency sums to zero; every balance equals its postings. |
| Append-only | High (audit) | Update, delete and truncate on postings and transactions are rejected by triggers (pgTAP). |
| `transfer_money` | High (moves money) | `security definer`, actor from `auth.uid()`, confirmed recipients only, idempotency key namespaced per sender and bound to the request (a reused key with another request is refused), 20 per hour. Visitors cannot call it. |
| Welcome grant | Medium | Paid once per account (idempotency key), only after the email is confirmed, so replaceable reservations never hold money. |
| Web | Medium | Amounts parsed to hundredths without guessing thousands separators; one idempotency key per request, kept across retries; errors mapped to copy; the statement is a captioned table with a currency filter. |
