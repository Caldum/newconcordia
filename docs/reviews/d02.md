# D02 review

Review of `feat/d02-clock` against `docs/plans/d02-clock.md`, following the `requesting-code-review`
checklist and the `differential-review` method. Size: small; strategy: deep.

## Risk triage

| Area | Risk | Notes |
| --- | --- | --- |
| `public.run_job` (security definer) | High | Executes dynamic SQL. The job name is checked against `game.scheduled_jobs` before `format('%I')`, so only registered `game.job_*` functions run. `EXECUTE` revoked from `public`, `anon`, `authenticated`; granted to `service_role` only (tested). |
| `game.now()` override | High | `game.fixed_now` is honored only when the session user is not `authenticator`, the role PostgREST uses for every API request. Players cannot reach `SET` through the API anyway; this is defense in depth. |
| Clock Worker | Medium | Holds the secret key. It only calls `run_job`; the key travels in `apikey` (and as bearer only for legacy JWT keys). Response bodies of failed calls are not logged. |
| Deploy step | Medium | The secret is written to `$RUNNER_TEMP`, passed with `--secrets-file` and removed by a trap. |

## Adversarial pass

- **Replay / double trigger:** Cloudflare may retry a cron; the slot key makes the second call a no-op
  (pgTAP and the end-to-end run).
- **Concurrent triggers:** the second insert waits on the unique key and then sees the committed status.
- **Partial effects on failure:** the job runs in a subtransaction; a failure rolls back its writes and is
  recorded with the error (pgTAP).
- **Clock tampering:** see `game.now()` above.

## Findings

- Critical: none. Important: none.
- Minor (accepted): the supply-chain collector could not reach OSV from this environment, so advisory status
  for the new packages comes from `pnpm audit` (no known vulnerabilities). No new package runs install scripts.
