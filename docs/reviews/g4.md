# G4 review

Review of `feat/g4-bills` against `docs/plans/g4-bills.md` and spec sections 2, 3 and 12.5.
Size: medium; strategy: money paths first (escrow, execution, release), then counting, then permissions.

| Area | Risk | Notes |
| --- | --- | --- |
| Escrow | High | The hold is taken in the same transaction as the bill; insufficient free funds refuse it. Every terminal state except `executed` releases open holds; the test checks no reservation stays open and the ledger balances. |
| Atomic execution | High | `game.execute_bill` runs inside a `begin … exception` block: a failure rolls back its effects (including a partial capture) and the bill ends `not_executed` with its code. |
| Counting | High | Integer cross-multiplication; seats fixed at presentation; no approval without a valid vote; the tie-break only on `yes = no`. |
| Initiative | Medium | The mandate row is locked while counting the allowance, so concurrent proposals cannot exceed it. |
| Web | Low | Components only render; the database checks offices, ranges and funds again. |

Accepted: decrees are text only; no notification of new bills until the messages module.
