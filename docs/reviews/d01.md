# D01 review

Review of `feat/d01-repositorio` against `docs/plans/d01-repository.md`, following the
`requesting-code-review` checklist and the `differential-review` method (risk-first, adversarial pass).
Codebase size: small; strategy: deep (every changed file read).

## Risk triage

| Area | Risk | Notes |
| --- | --- | --- |
| `supabase/migrations/*_security_baseline.sql` | High (permissions) | Only revokes privileges and creates an empty private schema. Closes access; opens nothing. |
| `.github/workflows/*.yml` | High (supply chain, secrets) | Actions pinned by SHA, `permissions: contents: read` by default, `persist-credentials: false`, secrets only in the deploy job behind GitHub environments. |
| `apps/web/public/_headers` | Medium | Strict CSP without `unsafe-*`; tested by unit test and checked live through `wrangler dev` in e2e. |
| `apps/web/src/i18n/*` | Low | Pure functions and a provider; storage access guarded. |

## Adversarial pass

- **Workflow injection:** no untrusted context (`github.head_ref`, PR titles, branch names) is interpolated
  into `run:` scripts. The deploy warning uses the `WRANGLER_ENV` variable, which can only be `production`
  or `staging`. `workflow_dispatch` on another branch cannot reach secrets: environments restrict the
  deployment branches (`docs/setup.md`, step 1).
- **Privilege drift:** a future migration that forgets a `revoke` or creates a table without RLS fails the
  catalog-scanning pgTAP invariants in CI.
- **Secret exposure:** only public values (`VITE_*`) reach the web build; the secret key is never referenced.
- **Clickjacking / XSS hardening:** `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `object-src 'none'`,
  `base-uri 'self'`.
