# R3 review

Review of `feat/r3-goods-and-lots` against `docs/plans/r3-goods-and-lots.md` and spec sections 1 and 5
(`requesting-code-review`, `differential-review`, `supabase-postgres-best-practices`). Size: large (every stock
path changes); strategy: follow each unit from creation to consumption.

| Area | Risk | Notes |
| --- | --- | --- |
| Negative stock | High | Lots keep `quantity >= 0`; `take_goods` locks the holder's lots, checks the total and only then subtracts, oldest first, so a refused take changes nothing (pgTAP acceptance). |
| Origin | High (future embargoes) | Set only by production (company country), the grant (citizen country) and the data migration; a trigger refuses changing a lot's holder, good or origin. Moves, offers, purchases and withdrawals carry it (pgTAP acceptance for each). |
| Data migration | High (destructive) | Inventories and depots are summed into lots in the same transaction before their tables are dropped; old codes map through `replaced_by`. Purchased goods get the holder's country as origin because the old tables never stored one. Leave this PR's merge to the owner (destructive data change). |
| Production | Medium | Inputs are taken from the depot's lots and logged as `production_input`; retired goods produce nothing. |
| Market | Medium | One origin per offer; the default picks the oldest lot that covers the quantity, so mixed holdings may need the seller to pick (`p_origin_country_code`). Tariff now follows the goods' origin. |
| Web | Low | New good names; Q1 food is eaten from the inventory; founding lists the spec's lines; every Q line can be upgraded. |

Accepted: retired fuel stays visible where players hold it; R5 decides companies whose good is fuel.
